# 小Lin风格知识/读书视频 SOP

目标不是“像小Lin说话”，而是复用她的生产方法：强观点、个人可信度、故事化解释、密集视觉支撑。现在我们的差距主要不在文字，而在画面信息密度。

## 质量标尺

如果小Lin原片是 100 分，我们之前约 10 分，常见原因：

- 只有口播，没有足够的 B-roll、信息图、标题卡、人物卡。
- 讲道理太多，具体故事太少。
- 选题没有“一句话结论”，观众不知道为什么要看。
- 每段画面没有服务观点，只是在填空。
- 字幕、封面、标题没有形成同一个钩子。

本 SOP 的及格线：每 10-20 秒必须出现一个视觉支撑，不允许连续一分钟纯口播。

## 适用内容

- 小说读后感
- 书单/作品推荐
- 商业、金融、社会科学科普
- “我读过/我体验过/我踩过坑”的个人知识分享

不适合：纯日常 Vlog、舞蹈卡点、只靠情绪的短口播。

## 一条片子的标准产物

在 `projects/<slug>/` 下保留：

```text
brief.md          选题、目标观众、核心结论
titles.md         标题候选和封面钩子
script.md         金字塔口播稿
storyboard.md     分镜和视觉支撑清单
asset-list.md     需要找/做的画面素材
audio/            配音或真人录音
exports/          横屏/竖屏成片
review.md         发布后复盘
```

## P0：参考校准

先读现有参考：

- `reference/商业金融书单/analysis.md`

这条参考沉淀出的核心模板：

```text
需求确认开场
→ 反套路立信
→ 预告结构
→ N 个单元，每个单元同一模板
→ 反转/彩蛋
→ 评论区互动
```

单个书/作品单元模板：

```text
报名字 + 一句轻松吐槽
→ 我和它的私人故事
→ 讲一个最抓人的具体故事/例子
→ 作者/背景/可信度
→ 适合谁 + 它改变了我什么
→ 顺带延伸一个同类推荐
```

## P1：选题和标题

使用 `content-plan`。

选题必须满足三个条件：

- 我真有体验：能讲私人故事，不只是百科。
- 观众有收益：看完能得到判断、避坑、书单、表达方式。
- 视觉可做：至少能准备 15 个画面支撑点。

输出 `titles.md` 时，每个标题都标注：

- 钩子类型：反常识 / 利益 / 情绪 / 悬念 / 身份认同
- 平台：B站横屏 / 抖音竖屏 / TikTok 多语
- 封面文案：最多 8-12 个字

## P1：写稿

使用 `script-pyramid`。

稿子强制金字塔：

```text
8秒钩子
→ 一句话结论
→ 3个支撑论点
→ 每个论点给故事/例子
→ 回扣结论
→ 评论互动
```

小Lin风格的写稿规则：

- 少讲概念，多讲故事。
- 每个抽象判断后面立刻跟一个例子。
- 口语化，但不松散。
- 先给结论，再解释为什么。
- 每 180-240 字约 1 分钟。

## P1：分镜

使用 `storyboard`，但要加一条硬规则：每段口播必须指定视觉支撑类型。

视觉支撑类型：

| 类型 | 用途 |
|---|---|
| A-roll | 本人口播，负责信任和情绪 |
| 书封面/作品图 | 锚定正在讲的对象 |
| 人物卡 | 作者、角色、公司、历史人物 |
| B-roll | 城市、交易所、书桌、电影感素材 |
| 文字清单 | 把问题、观点、关键词逐条弹出 |
| 信息图 | 金钱、时间线、人物关系、因果链 |
| 标题卡 | 章节切换，给观众进度感 |

分镜验收：

- 0-8 秒必须有强钩子和视觉变化。
- 每 10-20 秒至少一个视觉支撑。
- 每个“具体例子”必须配画面。
- 每个章节必须有标题卡或封面卡。
- 竖屏版字幕不能压住脸和核心图表。

## P2：素材和动画

优先级：

1. 自己拍的 A-roll 或桌面书本镜头。
2. 书封面、作者照片、公开资料图。
3. Remotion 做文字清单、时间线、对比图、数字动画。
4. 可商用/可引用 B-roll。

Remotion 适合做：

- 开场标题卡
- “三点清单”动效
- 人物关系图
- 数据对比卡
- 章节转场

不要为了动画而动画。每个动画必须回答一句口播里的“为什么/是什么/怎么变”。

## P2：配音

三种路线：

| 路线 | 什么时候用 |
|---|---|
| 真人录音 | 最像小Lin，信任感最高 |
| Qwen3-TTS | 快速出草稿、多语言 |
| 纳西妲 so-vits | 二创/角色声线试听，不建议严肃知识主号长期依赖 |

工具：

```powershell
# Qwen3-TTS / 整稿
cd tools\tts-mvp
.\.venv\Scripts\python.exe .\dub.py --lines script.txt --lang zh --speaker vivian --out outputs\narration.wav

# 纳西妲 so-vits 试听
.\tools\tts-mvp\nahida_sovits.ps1 -Text "你好，旅行者。" -Out .\nahida\sovits\outputs\demo.wav
```

交付前必须听：

- 首句
- 最长句
- 转折句
- 结尾互动句

## P2：剪辑和导出

使用 `edit-ffmpeg`。

基本顺序：

1. 录音或配音生成 `audio.wav`。
2. 组 A-roll、B-roll、标题卡、信息图。
3. 烧字幕。
4. 导出 B站横屏 16:9。
5. 导出抖音/TikTok 竖屏 9:16。

常用命令：

```powershell
.\.claude\skills\edit-ffmpeg\scripts\to_vertical.ps1 -Video ".\input.mp4" -Out ".\output_9x16.mp4" -Mode blur
```

## P2：封面

使用 `thumbnail`。

小Lin风格封面原则：

- 一个明确对象：书、人物、问题。
- 一个强短句：8-12 字。
- 不堆字，不做论文标题。
- 标题和封面互补：封面抛钩，标题补全收益。

示例结构：

```text
封面：这本书救了我的表达
标题：我为什么建议每个创作者都读一遍《金字塔原理》
```

## P3：复盘

使用 `review-data`。

每条片记录：

- 标题
- 封面文案
- 开场钩子
- 视觉密度：平均多少秒一个支撑画面
- 完播率
- 3秒/10秒留存
- 评论关键词

复盘判断：

- 标题吸不吸点击，看 CTR。
- 开场强不强，看 3秒/10秒留存。
- 内容撑不撑，看平均观看时长。
- 选题值不值继续做，看收藏和评论质量。

## 一句话工作流

```text
参考拆解
→ 选题标题
→ 金字塔稿
→ 分镜视觉清单
→ 素材/动画
→ 配音/录音
→ 剪辑字幕
→ 横竖屏导出
→ 封面
→ 复盘
```

只要分镜阶段认真做“视觉支撑清单”，质量会从 10 分先拉到 40-50 分；剩下的差距再靠真人表现、画面审美和剪辑节奏慢慢磨。
