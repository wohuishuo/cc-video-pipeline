# Transformers 5 / Intel Arc 140T 实验结论

实验目录：`projects/qwen3-tts-xpu-v5-fork`。完整工程记录见该目录的 `EXPERIMENT.md`。

## 2026-06-21 实测

固定 128 token、约 10.15 秒输出：

| 模式 | 冷态耗时 | 同进程热态 | 说明 |
|---|---:|---:|---|
| XPU eager | 52.8s | 27.5s | 比生产 CPU 没有数量级优势 |
| XPU compile | 348.6s | 13.64s | 热态约 9.4 token/s，约 0.74×实时 |
| compile 重启后首句 | 122.84s | 后续约 13.6s | 磁盘缓存不能替代进程内预热 |

上游“约 60×”是相对极慢 CPU 基线（约 0.1 token/s）与 B580 独显的口径；其 compile 相对自身 XPU eager 约 2.2×。本机 Arc 140T 实测 compile 相对 eager 约 2×。

## 未通过的生产门槛

- Transformers 5 分支短句不能可靠产生 EOS，`max_new_tokens=600` 会跑满并输出约 47.9 秒。
- 128-token 仅用于隔离吞吐，不能证明停句、长文或音质正确。
- 修复 EOS 后，依次验证：短中长句自动停止、纳西妲中英日俄音质 AB、30 分钟连续朗读、进程重启预热。

## 推荐服务形态

`阅读 App -> localhost HTTP TTS 服务 -> 常驻模型 -> 长度桶队列 -> WAV/流式音频`

启动时分别预热短句、中句、长句形状。相似输入复用已编译图；首次遇到新形状可能再次编译。服务退出后，下一次启动仍有追踪与加载成本。
